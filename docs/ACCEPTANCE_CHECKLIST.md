# Приёмочный чек-лист CheckStock

Проверяйте тестовый сценарий на **новом уникальном SKU** `DEMO-<дата>` (или аналогичном). Не рассчитывайте на исходные 25 шт. на базе, где уже проводились операции. Открывайте раздел «История» после каждого важного шага.

## Запуск и авто-тесты

- [ ] `docker compose up --build -d` завершилась без ошибки.
- [ ] `http://localhost:8000/` открывается, `/health/db` отвечает `connected`.
- [ ] `docker compose exec web alembic current` показывает `002_transfer_cancellation`.
- [ ] `docker compose --profile test run --build --rm tests` показывает `20 passed`.
- [ ] `docker compose exec web python -m scripts.check_integrity` выдаёт `OK` (без параллельных операций).

## Сквозной сценарий на отдельном SKU

1. [ ] Создать новый SKU `DEMO-<дата>` через «Остатки и товары».
2. [ ] Приход на Север **12**, на Юг **6**. Проверить физически 12/6, доступно 12/6.
3. [ ] Резерв FBS на Севере **8**: физически 12, резерв 8, доступно 4.
4. [ ] Попытаться зарезервировать ещё **5** с Севера: отказ, ничего не изменилось, хотя на Юге свободно 6.
5. [ ] Отменить первый FBS резерв: физически 12, резерв 0, доступно 12.
6. [ ] Зарезервировать и отправить FBS **3** с Севера: физически Север 9, в пути клиенту 3.
7. [ ] Переместить **4** с Севера на Юг: Север 5, Юг 6, между ФФ в пути 4.
8. [ ] Подтвердить приёмку 4: Север 5, Юг 10, между ФФ в пути 0.
9. [ ] Отправить FBO **2** с Юга: Юг 8, FBO в пути 2.
10. [ ] Подтвердить приёмку FBO: Юг 8, принято маркетплейсом 2, FBO в пути 0.
11. [ ] Отправить ещё **1** единицу с Севера на Юг и отменить до приёмки: Север остаётся 5, Юг 8, число между ФФ в пути возвращается к нулю. Журнал фиксирует отправку и отмену.
12. [ ] Создать склад `DEMO-FF-<дата>`, оформить туда приход **1** единицы нового SKU, затем архивировать. Проверить остаток 1 и историю.
13. [ ] Проверить, что новые поступления на архивный склад отклоняются.
14. [ ] Через Swagger (`/docs`) повторить подтверждение уже принятого перемещения: `replayed: true`, остатки без изменений.
15. [ ] Открыть «История» и убедиться в последовательности событий.

**Итого по этому сценарию:** поступило 12 + 6 + 1 = **19**. На ФФ: Север 5, Юг 8, архивный склад 1; отправлено клиенту FBS 3, принято FBO 2; в пути 0. Сумма **5 + 8 + 1 + 3 + 2 = 19**.

Обратите внимание: в интерфейсе могут быть и другие SKU, поэтому сверяйте **именно новый SKU**, а не общие цифры всей базы.
